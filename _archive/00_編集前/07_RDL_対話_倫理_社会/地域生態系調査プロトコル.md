# 地域生態系調査プロトコル
*T2：運用層 / OP・SOCIAL / DRAFT v0.3*
*依存：RDL_Core / SILN分解の数理フレームワーク / RDL_中間設計図プロトコル / RDL_道具特性 / 構造破壊学_前提文書*

---

## ■ 0. 目的

本プロトコルは、地域を人口・所得・産業分類などの静的属性の集合としてではなく、

**人・仕事・家族・場所・技能・消費・信用・移動・ケアが循環する局所生態系**

として観測するための調査手順である。

目的は、あらかじめ「地域に必要な政策」を決めることではない。

まず、

- 何が存在しているか
- 何と何がつながっているか
- 何がどこを流れているか
- どの役割が循環を支えているか
- どこから外へ流出しているか
- どこで循環が詰まっているか
- 何が消えると連鎖的な破断が起きるか
- 何が次世代へ継承されているか
- そして、観測系そのものが何を見落としているか
- 観測行為そのものが地域をどう変えているか

を観測する。

その上で、地域固有の破断点と介入可能な接続を仮設する。

```text
地域 ≠ static{人口, 所得, 産業}
地域 ≈ dynamic{SILN_i, W_ij, Flow_k, B, ξ}

調査：
Inventory
→ Relation
→ Flow
→ Break
→ Regeneration
→ Vital Signs
→ Intervention Hypothesis
→ Re-observation
```

本プロトコル自体も固定規格ではない。

**地域だけを観測するのではなく、地域を観測している観測系も観測対象に含める。**

---

## ■ 1. 基本姿勢――人ではなく関係と役割を見る

本プロトコルでは、特定の文化・階層・職業を、そのまま生態類型としない。

「ヤンキー系」「職人」「農家」「若者」「高齢者」等のラベルは、観測入口として使用できる場合があるが、最終的な分析単位ではない。

見るのは、その人物が何者であるかではなく、

**地域の循環において何を担い、何と接続し、何を流しているか**

である。

同じ人物が、

- 労働者
- 親
- 消費者
- 技能保持者
- 情報媒介者
- 仲介者
- 地域行事の担い手
- ケア提供者

という複数の機能を同時に持つこともある。

```text
人物ラベル ≠ 生態機能

Person
↔ Role
↔ Relation
↔ Flow
```

表面上観測しやすい文化類型は、局所循環構造を発見する**プローブ**として有効な場合がある。

しかし、

```text
Good Probe ≠ Representative Sample
```

である。

観測しやすいものを、地域全体の代表とみなしてはならない。

## ■ 2. 観測アーキテクチャ

## 2.0 Baseline Discovery Phase――Coreを凍結する前に探す

初回調査を、そのまま Core Panel の第1波として扱わない。

まず、期間を限定した **Baseline Discovery Phase** を Exploratory Panel として実施する。

目的は、

- 地域の主要な役割群
- 主要Flow
- 観測しやすい構造と観測しにくい構造
- 候補となるVital Signs
- 反応性の高い質問
- プライバシー上の高リスク領域
- OPDとして固定すべき条件

を発見することである。

```text
Baseline Discovery
= Exploratory / Pre-Core

Baseline Discovery
→ Core Candidate
→ Freeze Review
→ Core_v1 Wave 1
```

Baseline Discovery の値を、Core_v1 の長期時系列へ自動接続してはならない。
ただし、観測法・標本・質問・処理系は OPD として記録する。

既存調査等を流用する場合は、その由来を `Legacy Baseline` と明示する。

---

## 2.1 Core Panel と Exploratory Panel

観測精度の改善と長期時系列の維持を、同じ観測系へ同時に要求しない。

本プロトコルでは観測を二層へ分ける。

```text
Core Panel
= 長期比較用の固定観測系

Exploratory Panel
= ξ探索用の可変観測系
```

### Core Panel

Baseline Discovery Phase 後の Freeze Review を経て、長期比較の基準線となる。

原則として以下を固定する。

- 観測対象
- 質問項目
- サンプリング法
- 観測時期
- 観測努力量
- 地理的B
- 集計方法
- 使用指標
- 欠測処理
- 使用する分析パイプライン

プロトコル本文が改版されても、Core Panel を自動的に変更しない。

### Exploratory Panel

以下を自由に変更できる。

- 新しい集団への探索
- 新しいインタビュー項目
- 新しいAI分析
- 新しいFlow候補
- 不可視ネットワーク探索
- 新しいRDL語彙・記述形式の試験
- 新しい地理Bの仮設

Exploratory Panel の値を、そのまま Core Panel の時系列へ接続してはならない。

---

## 2.2 Core Freeze・昇格・変更

Core Panel は固定するが、**固定されたまま放置すること**も破断候補とする。

Exploratory Panel の発見は、

```text
Exploratory Finding
→ Core Promotion Proposal
→ Shadow Core Candidate
→ Freeze / Promotion Review
→ {Coreへ昇格, Exploratory継続, 却下, 追加観測}
```

の経路で扱う。

正式な発議は Operator / Resident・Local Actor / Independent Reviewer のいずれからでも可能とする。AIは候補を提示できるが決定主体にはしない。

### 昇格検査

- 複数時点・複数情報源で反復して現れるか
- 欠落によって地域モデルや介入判断が大きく変わるか
- 系統的に取りこぼされている役割・集団・Flowではないか
- 長期反復可能な観測法を作れるか
- 観測反応性・プライバシー・再識別リスクが許容可能か
- 旧CoreとのBridgeが可能か

単一スコアで自動昇格させない。

### Shadow Core Candidate

直ちにCoreへ入れず、Exploratory側でCoreに近い周期・手順で一定期間観測し、継続可能性・測定安定性・反応性・コストを検査する。

### Core Panelを変更する場合

```text
Core_v1 ─────────────────
                ├ Bridge Period
Core_v2         ─────────────────
```

旧版と新版を一定期間並走させる。変換不能なら `Series_v1 / Series_v2` として分離保存する。

**連続性を装うより、系列が切れたことを記録する。**

### Core Staleness Review

一定期間ごとに、

> Exploratoryで得られた重要発見が、Coreから系統的に排除され続けていないか

をレビューする。Coreを変更しない判断にも理由を残す。

既存実測がある場合は `Legacy Core` として保存し、可能なら v0.3 Core と重複観測する。実測がない場合は Baseline Discovery Phase → Freeze Review → `Core_v1 Wave 1` の順で初回基準線を作る。

## 2.3 生態学から借用する観測原理

本プロトコルは、動物生態学の対象を人間社会へそのまま置換するものではない。

借用するのは、**観測の構造**である。

主に以下の考え方を弱く借用する。

- Occupancy：未観測と不在を区別する
- Resource Selection：存在と利用を区別する
- Spatial Ecology：生活圏・移動・密度を見る
- Connectivity：接続と流れを見る
- Food Web / Network：依存関係を単体でなく網として見る
- Vital Signs Monitoring：少数の指標を反復観測する
- Link-tracing / RDS的探索：不可視ネットワークへの到達法として利用する

これらを社会存在論として採用してはならない。

```text
Borrowed Method
→ RDL Translation
→ Human-Social Constraints
→ Break Conditions
```

---

## 2.4 Occupancy――「見えない」と「存在しない」を分ける

地域調査では、

> 行政から見えない
> 統計に載らない
> インタビューで名前が出ない

ことを、

> 存在しない

とみなしてはならない。

特に、

- 非公式な仕事紹介
- 親族による育児
- 仲間内の貸し借り
- 個人的な技能交換
- 非公式な集会場所
- 地域内の信用関係

は観測漏れしやすい。

```text
Observed(X)=0
→ {Absent(X), Undetected(X)}
```

の双方を保持する。

---

## 2.5 Resource Selection――「ある」と「使われる」を分ける

施設・制度・サービスの存在と、実際の利用を区別する。

```text
公民館がある ≠ コミュニティハブである
商店街がある ≠ 地域消費が循環している
職業訓練校がある ≠ 地元就業につながっている
保育施設がある ≠ 子育て負荷が下がっている
```

調査では、

```text
Available
Used
Sustaining
```

の三段階を分けて記録する。

---

## 2.6 Spatial Ecology――行政境界と生活圏を分ける

居住地だけでなく、実際にどこを生活圏として使っているかを見る。

匿名化・集計を原則として、

- 通勤方向
- 買物圏
- 子育て移動
- 娯楽圏
- 実家との往来
- 学校
- 医療
- 車両整備
- 地域イベント

などから生活圏の重なりを仮設する。

```text
B_admin ≠ B_life
```

である可能性を常に保持する。

---

## 2.7 Connectivity――複数種類の流れを分ける

地域では、最低でも次の流れを分離して記録する。

```text
F_money   ：金
F_work    ：仕事
F_skill   ：技能
F_info    ：情報
F_trust   ：信用
F_care    ：育児・介護等
F_people  ：人の移動
F_goods   ：物資
```

金銭だけを追うと、地域を維持している無償の育児、紹介、信用、技能継承等を落とす。

---

## 2.8 Food Web的ネットワーク――単体ではなく循環を見る

捕食関係を借用するのではなく、**流れのネットワークを見る構造**だけを借用する。

例：

```text
建設会社
↓ 給与
従業員
↓ 消費
飲食店
↓ 発注
地元設備会社
↓ 雇用
若年者
↓ 定着
住宅需要
↓
建設会社
```

また、

```text
祖父母
↓ 育児時間
親
↓ 就業継続
所得
↓
家族生活の安定
↓
地域消費・家族形成余地
```

のように、貨幣以外の流れも同じ図上に置く。

---

## 2.9 可視性バイアスと不可視構造探索

観測しやすい集団だけで地域モデルを構築しない。

Exploratory Panelでは、

```text
Population Panel
    └ 無作為・層化抽出等

Network Reach Panel
    └ 紹介連鎖・リンク追跡

Targeted Blind-Spot Panel
    └ 既知の観測漏れ候補への探索
```

を使い分ける。

無作為抽出は人口属性の分布を見るには有効だが、W_ij の被覆には弱い。

不可視ネットワークへの到達には、紹介連鎖・リンク追跡・RDS的手法等を探索手段として利用できる。

ただし、それらの標本を地域人口全体の代表標本とはみなさない。

探索候補には、例えば、

- 家庭内部のケア網
- 女性中心の相互扶助
- 宗教共同体
- 外国人コミュニティ
- 非公式な高齢者ネットワーク
- オンライン中心の地域接続

等を含む。

目的は、**見えにくいW_ijへ到達すること**である。

---

## 2.10 Observation Reactivity――観測が地域を変える

本プロトコルでは、観測を地域の外側にある透明な行為とはみなさない。

質問、紹介連鎖、フィードバック、地図化、キー役割の提示等は、それ自体が W_ij・Flow・当事者の自己認識へ作用し得る。

```text
Observation O_t
→ ΔW
→ ΔFlow
→ ΔSelf-Recognition
→ M_B(t+1)
```

```text
Observation Reactivity
= 観測行為が対象構造へ与えた変化
```

を観測系の変数として保持する。

### Reactivity Log

必要に応じて、

```text
question_wording
named_or_role_based
prior_exposure_count
recontact_frequency
network_disclosure
researcher_introduced_connection
feedback_session
participant_reported_change
observed_relation_change
```

を記録する。

Core Panelでは、実名より役割ベースの質問、不必要な関係者一覧提示の回避、反復回数の記録等、低反応性形式を優先する。高反応性調査は Exploratory / Triggered Review 側へ分離する。

同一参加者への反復質問自体が行動を変える可能性があるため、可能なら Exploratory で `Repeated Panel vs Fresh Sample` の較正を行う。

観測によって構造変化が生じた場合は、

```text
Observation-induced Intervention
```

として別記録へ移し、純粋観測として扱わない。

**観測が対象を変えたことを、誤差として隠さない。**

## ■ 3. 調査単位――Functional Guild

人間を「種」に分類する代わりに、地域循環上の機能から**役割群（Functional Guild）**を仮設する。

| 役割群 | 主な機能 |
|---|---|
| 生活維持群 | 電気、水道、住宅、整備、修理 |
| 移動群 | 物流、配送、公共交通、車両 |
| 食料群 | 生産、加工、販売、飲食 |
| ケア群 | 育児、介護、医療 |
| 仲介群 | 仕事紹介、人材接続、信用仲介 |
| 経済循環群 | 店舗、地域企業、自営業 |
| 継承群 | 教育、弟子、事業承継、技能移転 |
| 集合場群 | 店、祭り、スポーツ、宗教施設、公共空間 |
| 外部接続群 | 域外市場、大学、行政、大企業、観光等 |

分類は固定しない。

一人・一組織が複数群へ属してよい。

## ■ 4. 実地調査手順

## 4.1 Inventory――何があるか

地域の構成要素を列挙する。

対象例：

- 人口構成
- 事業所
- 職業
- 技能
- 学校
- 店舗
- 医療
- 保育
- 住宅
- 交通
- 娯楽
- 地域団体
- 非公式集団
- 地域行事

この段階では重要度を決めない。

---

## 4.2 Habitat――どこで暮らしが回っているか

行政区ではなく生活機能でも地域を切る。

例：

- 住宅圏
- 工業圏
- 商業圏
- 学校圏
- 夜間活動圏
- 子育て圏
- 高齢者生活圏
- ロードサイド圏
- 駅前圏
- 港湾・農業圏

境界は重複してよい。

---

## 4.3 Relation――誰が誰を支えているか

主要な W_ij を聞き取り・観測から仮設する。

質問例：

- 困ったとき誰に頼むか
- 仕事はどこから来るか
- 人を雇うとき誰に聞くか
- 子どもを誰に預けるか
- 修理は誰に頼むか
- どの店によく行くか
- 地域情報は誰から入るか
- 新しく来た人は誰を通して地域へ入るか

ここでは「有名な人」ではなく、接続を多く持つ人・場所・組織を探す。

標準質問では可能な限り実名指定を避け、「誰が重要か」より「どの役割・場所・経路を通して支援が成立するか」を先に聞く。実名探索は Exploratory Panel へ分離し、Observation Reactivity を記録する。

---

## 4.4 Flow――何が流れているか

W_ij ごとに流量の種類を付ける。

```text
W_ij = {
 money,
 work,
 skill,
 information,
 trust,
 care,
 goods,
 people
}
```

可能なら、

- 頻度
- 方向
- 季節性
- 代替可能性
- 地域内 / 地域外

も記録する。

---

## 4.5 Leakage――何が外へ抜けているか

地域外流出を悪と決めつけない。

外部接続は資源・情報・人材を取り入れる経路でもある。

見るのは、**流出したものが何らかの形で戻っているか**である。

```text
地域 → 外部 → 地域
```

なら循環接続となり得る。

```text
地域 → 外部 → ∅
```

が継続し、代替も再流入もなければ、地域縮小方向へ作用する可能性がある。

対象例：

- 若者
- 所得
- 消費
- 企業利益
- 技能
- 教育投資
- 事業承継者

---

## 4.6 Regeneration――どう再生産されているか

地域の再生産を出生だけに限定しない。

```text
人の再生産      ：出生・転入・定着
技能の再生産    ：弟子・教育・継承
企業の再生産    ：起業・承継
関係の再生産    ：地域組織への新規参加
場所の再生産    ：店舗・施設・住宅の更新
文化の再生産    ：祭り・慣習・地域行事
```

地域が存続するには、複数の再生産が同時に必要になる。

---

## ■ 5. キー構造の検出――除去テスト

「重要人物」を主観で選ばない。

仮想的な除去テストを行う。

```text
Remove(SILN_i)
→ ΔW
→ ΔFlow
→ downstream failure
```

質問は単純でよい。

> この役割・機能がなくなったら何が困るか。  
> この技能を担う主体がいなくなったら、どの経路で代替されるか。  
> この集まり・場所がなくなったら、人はどこで接続するか。  

特定個人を名指しする除去質問は Exploratory / Triggered Review に限定し、Reactivity Log へ記録する。

除去したときに、

- 多数の接続が切れる
- 代替がない
- 複数種類の流れが同時に止まる
- 次世代への継承まで切れる

構造を、暫定的な**キーSILN**とする。

重要なのは規模ではない。

小さな整備工場、個人商店、一人の世話役等が、大規模施設より重い可能性もある。

---

## 5.1 キーSILNが個人へ帰着した場合

特定個人が地域ネットワーク上の単一障害点として検出されることはあり得る。

しかし、

```text
Remove(Person_i)
→ Network Break
```

が観測されても、

```text
Person_i = 高価値人物
```

とは記述しない。

代わりに、

```text
Role_R
occupancy = 1
redundancy ≈ 0
```

として、**その人物へ集中している役割構造の脆弱性**へ変換する。

政策対象は人物評価ではなく、

- 技能継承
- 役割の複線化
- 後継者形成
- 接続先の冗長化

等とする。

ただし、役割複線化を自動的な善としない。

当事者にとって、

- 所得
- 地位
- アイデンティティ
- 仕事量
- 事業価値

等が変化する可能性があるため、当事者を**介入対象ではなく交渉主体**として扱う。

---

## ■ 6. 観測指標と検出不確実性

v0.2では精密な単一指数化を急がない。

各指標は、観測値と推定値を分離する。

```text
Observed Metric
Estimated Metric
```

推定不能なら、

```text
Estimated = unresolved
```

としてよい。

**不確定な補正値を出すより、不確定性を残す。**

---

## 6.1 Observation Protocol Descriptor（OPD）

時系列比較では、観測法の同一性を記録する。

```text
OPD = {
  B,
  sampling_method,
  sampling_frame,
  recruitment_method,
  observation_unit,
  time_window,
  survey_duration,
  channel,
  inclusion_rule,
  exclusion_rule,
  observation_effort,
  observer_type,
  panel_type,
  question_wording_version,
  prior_exposure_count,
  reactivity_risk,
  AI_model/version,
  preprocessing,
  missing_data_rule
}
```

Core PanelではOPDを固定する。

AIモデルや前処理系を変更する場合、

- 旧パイプラインを維持して系列を継続する
- 過去のRaw Dataを新版で再処理し、別系列を作る
- Bridge Period を設ける

のいずれかを選び、黙って系列を接続しない。

---

## 6.2 検出確率

観測された量は概念上、

```text
Observed
≈ Detection × Actual + Error
```

と考える。

```text
Y_obs ≈ p_det × Y_actual
```

`p_det` を推定できる部分では、

- 同一対象への反復観測
- 独立した複数観測者
- 異なる観測チャネル間の重複

等を利用する。

推定不能なら、

```text
p_det = unresolved
```

とし、補正値を作らない。

その場合、同一Core Panel内での比較を優先する。

観測密度の増加による数値変化を、地域そのものの変化と誤認してはならない。

---

## 6.3 暫定循環指標

### 地域内循環率

```text
C_local_obs =
観測された地域内再投入Flow
────────────────
観測された総Flow
```

金銭・技能・ケア等は可能な限り分離して測る。

### 域外漏出率

```text
L_out_obs =
観測された戻り接続を持たない域外Flow
────────────────────
観測された総流出Flow
```

### 役割冗長度

```text
R_role =
同じ重要機能を独立して代替できるSILN数
```

これらは、検出率・観測努力量と併記する。

## 6.4 接続可能性を三値化する

辺を、

```text
Eligible
Ineligible
Unknown
```

へ分ける。

```text
E = E_yes ∪ E_no ∪ E_unknown
```

Unknown を Ineligible に落としてはならない。

接続密度は必要に応じて幅で示す。

```text
D_low =
|E_effective|
──────────────
|E_yes| + |E_unknown|

D_high =
|E_effective|
──────────────
|E_yes|
```

併せて、

```text
U_E =
|E_unknown|
────────
|E_total|
```

を表示する。

Unknown が大きい場合は、

> 接続密度は未確定

という結論を許容する。

`U_E` 削減のための追加探索は Exploratory Panel で行う。結果をCoreへ反映する場合は §2.2 の昇格・Bridge手続きを通す。

さらに、

- 平均有効接続数
- 役割群別接続数
- 橋接続数
- 冗長接続数

等も併記し、単一密度値へ圧縮しすぎない。

## ■ 7. Vital Signs・時間階層・観測負荷

## 7.1 Vital Signs

Baseline Discovery Phase 後に主要指標を Core Candidate として選び、Freeze Review 後に Core Vital Signs として固定する。

候補：

- 若年人口残存
- 地域内就業
- 地域内消費
- 事業承継
- 技能継承
- 新規起業
- 子育て支援接続
- 住宅取得・定着
- 地域ハブ利用
- 出生
- 転入 / 転出
- キー役割の**低反応性冗長性Proxy**

キー役割の冗長性を Core で追跡する場合、反復する除去テストそのものを Vital Sign にしてはならない。

Core 側では、例えば、

- 同一機能を担う事業所・組織数
- 資格・技能保持者数
- 後継者・補助担当の有無
- 求人・欠員の充足状況
- 代替サービスまでの距離・時間
- 主担当不在時のサービス継続状況

等の**低反応性Proxy**を優先する。

```text
Core
= Redundancy Proxy

異常・低下・矛盾
↓
Exploratory / Triggered Review
= Removal Test / 詳細聞き取り
```

除去テスト本体は §5 の通り Exploratory / Triggered Review 側に置き、Observation Reactivity を記録する。

重要なのは絶対値より、**同じCore Panelで繰り返して変化を見ること**である。

---

## 7.2 時間階層

地域生態の変数は同じ速度で動かない。

```text
短期：数週〜1年
  店舗利用
  就業
  移動
  地域イベント
  支援利用

中期：1〜5年
  定着
  起業
  住宅
  技能習得
  雇用構造

長期：5〜20年以上
  家族形成
  出生
  技能継承
  事業承継
  次世代定着
```

短期指標の改善を、長期成果の証明として扱わない。

```text
Leading Indicator ≠ Final Outcome
```

介入ごとに、

```text
Expected Response Window
```

を置く。

期待時間以前の失敗判定と、期限を黙って延長する無期限継続の双方を避ける。

期限を超えた場合は `Out-of-Window` として §13 のレビューへ送る。

---

## 7.3 観測負荷制御

厳密さによって調査自体が継続不能になることを破断として扱う。

すべての検査を全件には適用しない。

```text
Continuous Core
+
Sampled Audit
+
Triggered Review
```

の三段階とする。

### Continuous Core

低コストで反復可能な基本観測。

### Sampled Audit

往復翻訳、二重観測、詳細聞き取り等を層化した一部標本へ実施する。

Sampled Audit は **Exploratory Panel 側の検査**として扱い、Core Panel のOPDへ混入させない。

抽出率 `q_audit` は地域・予算・誤差状況に応じて設定する。翻訳残差・再識別リスク・Unknown が多い層には適応的に抽出を厚くしてよいが、その変更を `Audit_OPD` に記録する。

### Triggered Review

異常値、矛盾、個人特定リスク、重大な政策判断等が発生した場合だけ詳細検査へ入る。

```text
通常
→ 軽量観測

異常
→ 高密度観測
```

とする。

---

## 7.4 Governance Load――統治負荷を測る

観測負荷だけでなく、観測を正当に運営するための**統治負荷（Governance Load）**も記録する。

本プロトコルは、OPD・同意・撤回・反応性・翻訳・破断レビュー等を要求するため、厳密化そのものが運用主体を圧迫し得る。

```text
Governance Load ↑
→ 記録欠落
→ 形式的レビュー
→ 独立性低下
→ 未処理案件蓄積
→ 調査停止
```

を破断経路として扱う。

最低限、可能な範囲で以下を記録する。

工数だけでは、現場で脱落する理由を捉えきれない。特に、同意説明・撤回案内・Reactivity記録・除去テスト等は、所要時間が短くても社会的・心理的コストが高い場合がある。

したがって Governance Load は、単一工数ではなく**多次元コストベクトル**として扱う。

```text
Governance_Load = {
  C_time,          # 時間コスト
  C_money,         # 金銭コスト
  C_skill,         # 必要技能・習熟コスト
  C_social,        # 聞きにくさ・関係悪化・警戒を生むコスト
  C_psych,         # 記録疲労・心理的負担
  C_institutional, # 許可・倫理審査・制度調整

  survey_person_hours,
  review_person_hours,
  required_roles,
  meeting_count,
  log_maintenance_hours,
  external_review_cost,
  pending_review_count,
  overdue_withdrawal_count
}
```

各コストを無理に共通単位へ変換してはならない。目的は、**厳密さを維持するために調査そのものが破綻していないか、また何のコストによって破綻しているかを見ること**である。

特に、

```text
工数が軽い
AND
実施率が低い
```

場合、単純な怠慢と決めつけず、`C_social / C_psych / C_institutional` の見落としを疑う。

統治負荷が継続可能性を超える場合、検査を形骸化させるのではなく、§7.5 の縮退構成へ明示的に移行する。

---

## 7.5 Minimum Viable Configuration――縮退を正規運用にする

本プロトコルは、すべての地域・組織がフル構成を運用できることを前提としない。

簡略化は許容する。

ただし、簡略化によって失うものを「精度低下」とだけ表現してはならない。

**省略した観測・検査に対応して、主張可能範囲そのものを縮小する。**

### 7.5.1 削れるもの / 削れないもの

```text
削れる：
  観測粒度
  観測頻度
  地理的被覆
  Flow種類数
  Vital Signs数
  Audit率
  Exploratoryの規模
  外部レビュー頻度

原則として削れない：
  観測条件の記録
  同意・撤回の最低限
  Reactivityの最低限記録
  出力層の区別
  再識別Release Gate
  その構成で主張できないことの明示
```

後者は、後から復元できない情報・権利・制約だからである。

最短原則：

> **削れるのは観測量。削れないのは、観測条件と主張限界の記録。**

### 7.5.2 Configuration S / M / L

T0〜T5 の文書Tierと混同しないため、運用規模は `Configuration` と呼ぶ。

| 構成 | 想定 | 必須範囲 | 主張可能範囲 |
|---|---|---|---|
| **Config S** | 一人〜少人数・短期 | Baseline Discovery、簡易OPD、同意/撤回、最小Reactivity記録、Privacy Gate、ξ/破断候補 | 関係候補・Flow候補・破断候補・追加調査仮説 |
| **Config M** | 小チーム・複数年 | 低頻度Core、限定Vital Signs、スポットExploratory、OPD、基本Audit、定期外部レビュー | 同一Core内の傾向・構造変化候補・限定的政策仮説 |
| **Config L** | 十分な人員・長期 | 本プロトコルのフル構成 | より強い比較、独立監査付き評価、複数層をまたぐ長期検証 |

Config S は**下見 / Baseline Discovery**として扱い、Core を凍結しない。

```text
Config S
→ Baseline Discovery
→ Freeze Review
→ Config M/L で Core_v1
```

したがって、Config S の観測値から時系列傾向を主張してはならない。

### 7.5.3 省略と主張不能の対応

縮退時には、最低限以下の対応を明示する。

| 省略・未実施 | 主張してはならないこと |
|---|---|
| Core Panelなし | 時系列的な増減・傾向 |
| `p_det` 推定なし | 絶対的な存在率・密度・観測完全性 |
| Exploratoryなし | 「見つからなかったから存在しない／重要でない」 |
| Reactivity記録なし | 観測前後の差が観測行為と独立した地域変化である |
| Independent Reviewerなし | 「破断条件が独立に検査され、不在だった」 |
| Case_OPDなし | 他地域事例との比較を政策根拠として用いる |
| Translation Validationなし | RDL翻訳が原情報の意味を十分保持している |
| Release Gateなし | Key SILN・詳細W_ij等を Policy / Public 層へ安全に出力する |
| 同意・撤回手続きなし | 個人由来データを継続利用する正当性 |
| BridgeなしでCore変更 | 変更前後を単一の連続系列として扱う |

ここで、

```text
未検査 ≠ 不在
省略 ≠ 無影響
Reduced Configuration ≠ Full Configuration
```

とする。

### 7.5.4 Configuration Declaration

各調査は開始時・改構成時に、

```text
Configuration Declaration = {
  config_level,
  implemented_components,
  omitted_components,
  claim_limits,
  responsible_operator,
  next_review
}
```

を残す。

縮退構成でフル構成相当の結論を出すことを、破断条件とする。

### 7.5.5 Claim Envelope――主張限界を成果物から分離しない

Configuration Declaration を文書冒頭だけに置いてはならない。

成果物が行政資料・会議資料・二次報告書等へ切り出された場合でも主張限界が失われないよう、**各図表・ネットワーク図・要約出力そのものに構成レベルと主張限界を埋め込む。**

```text
Artifact = {
  content,
  config_level,
  claim_limits,
  OPD_ID
}
```

これを `Claim Envelope` と呼ぶ。

Config S の標準例：

```text
Configuration: S
Use: Exploratory / Baseline Discovery only
Claim Limits:
  - No temporal trend claim
  - No population prevalence claim
  - No causal claim
  - No individual policy targeting
OPD_ID: ______
```

`Claim Envelope` を外した転載・再利用は、本プロトコル準拠成果物として扱わない。

## 7.6 Pre-field Cost Hypothesis と Pilot 0

Config S の実行可能性は、事後評価だけでは判定しない。

実施後に「重かった」「想定内だった」と評価すると、結果が事後的説明へ吸収され、破断検査にならないためである。

### 7.6.1 コスト予測の事前登録

Pilot 0 または Baseline Discovery 開始前に、最低限以下を記入する。

```text
Pre-field Cost Hypothesis = {
  predicted_total_time,
  predicted_money_cost,
  predicted_skill_requirements,
  predicted_social_cost,
  predicted_psychological_cost,
  predicted_institutional_cost,

  item_costs: {
    OPD,
    Consent,
    Withdrawal,
    Reactivity_Log,
    Interview,
    RDL_Translation,
    Privacy_Check,
    Output_Preparation
  },

  predicted_first_failure_item,
  predicted_failure_reason,
  break_threshold
}
```

特に `predicted_first_failure_item` を必須とする。

「原則として削れない」とした項目が実地で最初に脱落した場合、それは現場側の失敗ではなく、**§7.5.1 の分類または実装形式の破断候補**として扱う。

### 7.6.2 破断閾値

閾値の値は対象・規模によって異なるため固定しないが、実施前に設定する。

例：

```text
実測総時間 > 事前予測 × k
OR
必須項目が実施不能
OR
C_social / C_institutional が許容範囲を超過

→ Config S 実行可能性仮説に破断候補
```

`k` を事後に変更してはならない。変更する場合は、旧判定と新判定を併記する。

### 7.6.3 Pilot 0――Config S自身を被験対象にする

最初の実地試験では、地域生態系全体の把握を目的にしなくてよい。

まず、**Config S の手順そのものが実行可能か**を破壊検査する。

暫定最小形：

```text
対象：調査者自身の生活圏等
規模：5〜10人程度
質問：§4.3 から3項目程度

最低記録：
  簡易OPD
  同意説明
  撤回案内
  Reactivity
  実時間
  多次元コスト
  簡易RDL化
  Privacy Check
```

人数・質問数は固定規格ではない。目的は人口推定ではなく、運用手順の破断検査である。

### 7.6.4 Protocol Adherence Map

Pilot 0 では、地域について何が分かったかより、**設計された手順が実際にどこまで実行されたか**を主要成果とする。

```text
Protocol Adherence = {
  Planned,
  Executed,
  Skipped,
  Reason,
  Cost_Type,
  Reactivity_Observed
}
```

例えば、

```text
Reactivity Log
Planned: yes
Executed: 4/8
Skipped: 4/8
Reason: 会話直後に記録を忘れた
```

なら、単純な人的ミスとして閉じず、

```text
Protocol_designed
≠
Protocol_executed
```

の差分をプロトコル側のξとして記録する。

この差分を `Protocol Adherence Map` として保存する。

### 7.6.5 Pilot 0 と版管理

Pilot 0 は v0.3 の**実行可能性検査**であり、それ自体を直ちに v0.4 への主要改版入力とはしない。

ただし、

- 「削れない」必須項目が実施不能
- 同意・撤回・Privacy Gate が構造的に成立しない
- 想定を大幅に超える Governance Load が発生

した場合は、安全・権利・実施不能性に関する仕様凍結例外として v0.3 を修正してよい。

それ以外の機能追加は Baseline Discovery まで凍結を維持する。

## ■ 8. 介入候補の生成

調査後に初めて政策を考える。

```text
観測
↓
破断点
↓
原因仮設
↓
最小介入
↓
再観測
```

例：

```text
仕事あり
住宅なし
→ 住宅接続への介入
```

```text
仕事あり
住宅あり
若者流出
→ 承認・娯楽・人間関係・所得等を再調査
```

```text
子ども希望あり
次子形成で停止
→ care flow の破断位置を調査
```

```text
技能需要あり
後継者なし
→ 継承 W_ij への介入
```

政策名から問題を探してはならない。

**破断を観測してから、道具を選ぶ。**

## ■ 9. 介入事例比較・適応前検査

他地域で成功した政策・制度・事業モデルを、そのまま対象地域へ適用してはならない。

ある地域で施策 X が成功したという事実は、

```text
X → Success
```

を意味するとは限らない。

実際には、

```text
X
× 既存の人間関係
× 産業構造
× 技能
× 信用
× 土地・住宅
× 行政能力
× 地域需要
× 歴史的経路
→ Outcome
```

であった可能性がある。

したがって観測単位は、

```text
Intervention X
+
M_B(region)
+
W_ij
+
Flow
+
History
+
ξ
```

とする。

---

## 9.0 Case Observation Descriptor（Case_OPD）

他地域の介入事例は同一の観測法で得られたとは限らない。

```text
Case_OPD = {
  source_type,
  source_actor,
  collection_channel,
  observation_date,
  intervention_start/end,
  follow_up_horizon,
  outcome_definition,
  failure_definition,
  reporting_incentive,
  funding_relation,
  missingness,
  search_channel,
  verification_level
}
```

不足している場合は `Case_OPD = incomplete` とし、排除せず証拠強度を下げる。

成功・失敗ラベルより先に、**誰が・いつ・どの基準でそう記録したか**を見る。

---

## 9.1 成功例だけを見ない

対象集合を、

```text
Case = {
  success,
  partial_success,
  no_effect,
  interruption,
  failure,
  deterioration,
  unresolved
}
```

とする。

成功例は作用可能性を示し、失敗例は破断条件を示す。

両方が必要である。

---

## 9.2 失敗事例を能動的に探す

失敗事例は自然には残りにくいことを前提とする。

探索候補：

- 中途終了した事業
- 目標未達となった事業
- 撤退した事業者
- 打ち切られた補助事業
- 住民の「続かなかった」証言
- 維持不能となった施設・組織
- 成功報告後に消失した事例

成功例探索と失敗例探索について、

```text
search_effort_success
search_effort_failure
```

を記録する。

同数の事例が集まることは要求しない。

**集めようとした努力量そのものを記録する。**

---

## 9.3 同一施策の成功 / 失敗ペアを必須としない

```text
X成功 vs X失敗
```

という完全対応例は希少である。

事例比較から直接因果を確定しない。

代わりに、

```text
Repeated Condition
Repeated Break
Repeated Dependency
```

を蓄積する。

事例数が少ない段階では、**因果法則ではなく破断候補ライブラリ**として扱う。

---

## 9.4 地盤適合性の検査

### 宿主条件

その介入を受け止める既存構造があるか。

- 人間関係
- 組織
- 事業者
- 信用
- 利用者集団
- 地域ハブ

### 資源条件

介入を維持する資源があるか。

- 人材
- 技能
- 土地
- 建物
- 資金
- 時間
- 需要

### 接続条件

介入によって強化されるべき W_ij が存在するか。

```text
X
→ W_ab 強化
→ Flow 増加
```

を期待しているにもかかわらず、

```text
W_ab ≈ ∅
```

なら、X単体では作用しない可能性が高い。

### 代謝条件

投入された資源が地域内部を循環するか。

```text
補助
→ 事業
→ 地域雇用
→ 地域所得
→ 地域需要
```

となる場合と、

```text
補助
→ 外部主体
→ 域外流出
```

では作用が異なる。

### 再生産条件

外部支援終了後も構造が維持・更新されるか。

```text
Support = 0
```

となった瞬間に消滅するなら、地域生態へ定着していない可能性がある。

### 競合条件

新しい介入が、既存の有効な地域循環を破壊しないか。

```text
大型施設導入
→ 利便性向上
→ 既存小規模ハブ消滅
→ 非公式ネットワーク消失
```

のように、表面的な改善が別の W_ij を破断する可能性がある。

---

## 9.5 移植ではなく適応

```text
X_A
↓ 分解
{作用核, 前提条件, 破断条件}
↓
B地域の M_B と比較
↓
X_B'
```

とする。

```text
X_A ≠ X_B'
```

であってよい。

外見上異なる施策になっても、同じ破断点へ作用するなら構造的には同型の介入となり得る。

---

## 9.6 採用しないことも成果

地盤適合性が低ければ採用しない。

```text
fit(X, M_B(region)) → low
→ reject
```

これは失敗ではない。

**不適合な成功事例を導入しないこと自体が、調査の成果である。**

---

## ■ 10. AI活用

地域生態系調査では、人口統計、事業所情報、交通、地図、行政資料、インタビュー、地域史、店舗情報、自由記述等、形式の異なる大量の情報を横断して扱う。

AIは、

**地域住民を評価・分類する装置**

ではなく、

**分散した観測情報から関係構造を暫定的に復元する補助装置**

として使用する。

```text
AI role
≠ Person Evaluation
≠ Policy Decision

AI role
= Observation Assist
+ Pattern Extraction
+ Relation Hypothesis
+ Anomaly Detection
+ Re-observation Support
```

---

## 10.1 基本運用循環

```text
現地観測
↓
資料・統計・聞き取り
↓
AIによる暫定構造抽出
↓
RDL記述
↓
人間による現地検証
↓
修正
↓
再観測
```

AIが提示した SILN・W_ij・Flow はすべて、**現地検査を待つ仮設**として保持する。

---

## 10.2 自由記述・聞き取りの横断分析

AIが特に有効なのは、多数の自然言語記録から繰り返し現れる関係を抽出する作業である。

例：

```text
A整備工場
├─ 修理
├─ 仕事紹介
├─ 地域情報
├─ 若年者の集合
└─ 中古車仲介
```

行政統計では一事業所にしか見えない対象が、実際には複数機能を持つキーSILN候補である可能性がある。

AIは、このような**分類をまたぐ接続構造の発見**に用いる。

---

## 10.3 事前分類を弱くする

```text
先分類 → 観測
```

だけでなく、

```text
観測
→ Pattern
→ 暫定分類
→ 再検査
```

という逆方向も許容する。

年齢・所得・職業・学歴等の既存分類を捨てるのではなく、それだけに観測を閉じない。

---

## 10.4 GIS・ネットワーク解析との接続

匿名化・集計された情報から、

```text
居住
→ 就業
→ 買物
→ 保育
→ 実家
→ 医療
→ 娯楽
```

等の移動を重ね、実生活圏 `B_life` を仮設する。

またネットワーク解析により、

- 多数の関係が集中するハブ
- 複数集団をつなぐ橋
- 代替困難な役割
- 地域外への主要流出口
- 接続されていない集団
- 継承者のいない技能
- 除去すると分断されるSILN

等の候補を探す。

ただし、

```text
centrality 高
→ 重要
```

と自動判定しない。

数理的中心性と地域的重要性は異なり得る。

---

## 10.5 複数BによるAI分析

必要に応じて異なるBを持つ分析を並列化する。

```text
AI_population ：人口・移動
AI_economy    ：所得・消費・事業
AI_skill      ：技能・産業・継承
AI_care       ：育児・介護
AI_mobility   ：交通・生活圏
AI_relation   ：人間関係・信用
```

```text
{M_B1, M_B2, ... M_Bn}
↓
共通構造
+
非一致
+
矛盾
↓
現地再調査
```

一致だけでなく、AI間の不一致を重要なξ候補として扱う。

---

## 10.6 AIによる未説明候補の生成

AIには答えだけでなく、現在のデータでは説明できないものを出力させる。

ただし、AIが生成できるのはAI自身のB内部で表現可能な未知候補に限られる。

```text
ξ_AI_candidate ≠ ξ
```

である。

AIが何も指摘しなかったことを、ξが存在しない証拠にしてはならない。

---

## 10.7 ξ候補をKPI化しない

「ξ候補が実観測へ転換された割合」を目標値として最適化してはならない。

各候補について、必要に応じて、

```text
Confirmability
Distance_from_current_M_B
Potential_impact
Source_diversity
Follow_up_status
```

等を記録する。

ただし、これらもランキング最適化用の単一スコアへまとめない。

特に、**確認困難だが既存モデルから遠い候補**を一定量残す。

```text
Easy-to-confirm only
→ 禁止
```

AIによるξ候補列挙が儀礼化し、実際の再観測圧力を下げる場合は破断として扱う。

---

## 10.8 AIを政策決定主体にしない

```text
AI：
「この地域にはX政策が最適」
↓
自動採用
```

を禁止する。

政策決定は、

```text
AI仮設
→ 現地検査
→ 住民反応
→ 制度条件
→ 破断検査
→ 人間による判断
```

を経る。

---

## 10.9 個人予測を政策対象化しない

以下の利用を禁止する。

```text
「この人物は地域定着型」
「この若者は流出可能性が高い」
「この家庭は出生可能性が高い」
「この層は政策効率が良い」
```

本調査の対象は、人間の価値や将来ではなく、地域に存在する関係構造である。

```text
Person Score ×

W_ij / Flow / Break / Regeneration ○
```

---

## 10.10 AIの位置

```text
地域住民
= 生態系の構成者
+ 観測情報の提供者

統計・資料
= 長期観測記録

現地調査員
= B設定
+ 観測
+ 仮設検証

AI
= 情報圧縮
+ 関係抽出
+ 仮設生成
+ 未説明候補生成

RDL
= 異種観測を比較可能な形へ変換する中間言語
```

AIは地域の外側から正解を与える存在ではない。

**観測密度を上げ、仮設と破壊検査の循環速度を上げる道具**として位置づける。

---

## ■ 11. RDLを中間言語として使用する

地域生態系調査では、扱う情報の形式も、観測者の語彙も統一されていない。

```text
行政統計
GIS・地理情報
企業・店舗情報
インタビュー
自由記述
地域史
人口移動
ネットワーク解析
AI分析
現地観察
```

これらを直接統合すると、同じ対象を異なる語彙で記述しているため比較が困難になる。

そこで一度、RDL表現へ変換する。

```text
Raw Observation
↓
Domain Interpretation
↓
RDL Representation
```

最低限、

```text
B       ：何を対象として切ったか
SILN    ：一時的に安定している構造
W_ij    ：構造間の接続
Flow    ：何が接続を通って流れているか
Break   ：破断・詰まり
ξ       ：未観測・未説明・不一致
```

として記述する。

RDLは、**答えを統一するためではなく、異なる観測を比較可能な関係記述へ変換するための中間言語**として使用する。

---

## 11.1 異なるBを単一モデルへ潰さない

```text
M_B(population)
M_B(economy)
M_B(care)
M_B(skill)
M_B(mobility)
```

等を並存させる。

比較によって、

```text
一致点
非一致点
矛盾点
未説明点
```

を抽出する。

```text
M_B1 ≠ M_B2
```

となった場所は、誤差として消去せず再観測対象として保持する。

---

## 11.2 RDL翻訳不能性を記録する

RDLへ変換できた情報だけを比較すると、RDL自身のBによる情報脱落を観測できない。

すべての翻訳で、少なくとも **Sourceへの追跡可能な参照** と翻訳対応を保持する。Raw Source 本体の保持期間は §12 に従い、無期限保持を要求しない。

```text
Source Reference
↓
RDL Translation
↓
Reconstruction
```

を行い、

```text
Source ≠ Reconstruction
```

となる差分を、

```text
ξ_translation
```

として記録する。

最低限、

```text
Mapped
Partially Mapped
Unmapped
```

の三状態を持つ。

```text
Unmapped → discard
```

としてはならない。

```text
Unmapped
→ ξ_translation
→ Schema Review
```

とする。

RDLは、すべてを記述できる言語ではなく、**どこまで記述でき、どこから記述できないかまで記録する中間言語**として使う。

---

## 11.3 往復翻訳を同一AIだけで閉じない

AIが翻訳し、同じAIが再構成を評価すると、同一B内で一貫した歪みは差分に現れない。

### 発話データ

可能なら再構成された自然言語を元発話者へ戻し、

```text
意味保持
欠落
追加
変形
判定不能
```

を確認する。

### 文書・統計・専門資料

別Bを持つ人間レビュー者、または独立した第二分析系が確認する。

元発話者へ戻せない場合、

```text
RoundTrip = unvalidated
```

を明示する。

```text
Traceability = 全件
Validation = 標本またはトリガー
```

と分離し、実検証は §7.3 の Sampled Audit / Triggered Review で行う。

---

## 11.4 RDL自身も更新対象とする

実地調査の中で、

- Flowでは表せない関係
- SILNとして切りにくい構造
- Bが急激に変動する事例
- 複数AI間で翻訳不能な情報

が現れた場合、データをRDLへ無理に合わせない。

```text
Observation ∉ Current RDL
↓
Observation を捨てる ×

RDL Schema を再仮設 ○
```

ただし、RDL Schema更新によって Core Panel の長期系列を自動的に書き換えない。

探索系の更新と基準尺の維持を分離する。

---

## ■ 12. 人間社会への適用禁止事項・データ統治

## 12.1 ラベル固定を禁止する

```text
「ヤンキーだから地域循環型」
「高学歴だから流出型」
```

等の属性からの決め打ちは行わない。

---

## 12.2 個人追跡の常態化を禁止する

生活圏調査は個人監視を目的としない。

原則として匿名化・集計・自発的提供情報を用いる。

---

## 12.3 出生を人間価値へ変換しない

人口再生産への寄与を個人の価値評価へ変換しない。

出生は地域循環の一変数であり、人間評価尺度ではない。

---

## 12.4 ローカル閉鎖を最大化しない

地域内循環率を100%へ近づけることを目標としない。

外部との接続は、新しい資源・技能・情報・文化的多様性等の流入口にもなり得る。

目標は閉鎖ではなく、

**地域内部で生存可能な循環を持ちながら、外部とも交換可能であること**

とする。

---

## 12.5 調査参加への同意・撤回

直接インタビュー、追跡調査、自由記述等では、調査開始前に少なくとも、目的・取得データ・利用範囲・再連絡・保存期間・公開粒度・撤回可能範囲を説明し、同意を得る。

再連絡・長期追跡・音声記録等は必要に応じて別同意とする。

参加者は、自身が直接提供したデータの利用停止・撤回を申し出られるようにする。ただし、既に不可逆に集計された統計、既公開成果物、他者から独立に提供された情報まで自動的に消去できるとは限らない。この限界は同意時に明示する。

```text
Withdrawal Request
→ Raw / Research Layer確認
→ 除外可能範囲を処理
→ Derived Analysisへの影響確認
→ Withdrawal Log
```

撤回しにくい空気を地域ハブや行政が作ること自体を破断候補とする。

行政統計・公開資料等は、直接参加同意とは別に適用法令・倫理・利用条件へ従う。

---

## 12.6 三層データ構造

```text
Raw Layer
↓
Pseudonymized Research Layer
↓
Structural Analysis Layer
```

### Raw Layer

- アクセス主体を限定する
- 保持目的・保持期間を事前に定める
- 同意・撤回状態を紐づける
- 不要となった識別情報は廃棄する

### Pseudonymized Research Layer

仮名化された調査データ。

### Structural Analysis Layer

`Role_R / W_ij / Flow / Redundancy` 等の構造を扱う。

---

## 12.7 再識別可能性

`Role_R / occupancy = 1` のように、小規模地域では構造記述だけで人物を推測できる場合がある。

名前を消したことを匿名化完了とはみなさない。

公開・政策判断層では、役割統合、地理・時間粒度低下、少数セル非表示、複数役割の束ね等によって再識別可能性を下げる。

---

## 12.8 成果物の出力層

```text
Research Layer Output
↓ Privacy / Consent / Re-identification Gate
Policy Decision Output
↓ Additional Aggregation
Public Output
```

Research Layer は権限を持つ調査主体のみが扱い、個人へ帰着し得る Key SILN や詳細 W_ij を含み得る。

Policy Decision Output では原則として、

```text
特定個人 → 役割脆弱性
```

へ変換する。

Public Output はさらに粒度を下げ、少数セル・希少役割・地理的手掛かり等を必要に応じて抑制する。

**Privacy Review は成果物の末尾項目ではなく、出力層を跨ぐ前のゲートである。**

---

## ■ 13. 破断条件と判定手続き

本プロトコル自体も破壊検査対象とする。

以下が生じた場合、B・観測法・介入を引き直す。

- 人間を固定的な「種」に分類し始めた
- 観測者の文化的好悪がキー構造判定へ侵入した
- 地域内循環を善、域外接続を悪として扱い始めた
- 出生率を人間価値へ変換した
- 観測されない関係を存在しないと断定した
- 数値化不能なケア・信用・文化を無価値として除外した
- 指標達成そのものが目的化した
- 住民の選択可能性を下げる介入が「地域存続」の名で正当化された
- 一度作った地域モデルを固定して更新しなくなった
- AI出力を現地観測より上位に置いた
- ξ候補の列挙が儀礼化した
- 観測精度を上げるための負荷が継続調査を破壊した
- Governance Load が運用能力を超え、ログ・レビュー・独立性が形式化した
- 縮退構成であることを隠し、フル構成相当の結論を主張した
- 個人特定リスクが構造分析上の利益を上回った
- 観測行為が W_ij / Flow / 当事者の自己認識を大きく変え、その作用が未記録のまま分析された
- Core Panel が長期間レビューされず、重要なExploratory発見が系統的に排除された
- 調査参加・撤回が地域内の権力関係によって事実上困難になった

---

## 13.1 判定主体

破断条件を作成者・運営者自身だけに判定させない。

最低限、

```text
Operator
Resident / Local Actor
Independent Reviewer
```

という異なるBを持つ主体から検査する。

AIは判定主体ではなく、

```text
Diagnostic Support
```

とする。

---

## 13.2 Independent Reviewer の独立性

独立性をラベルだけで保証しない。

事前に、

```text
Selection Rule
Funding Source
Conflict of Interest
Term
Removal Rule
```

を記録する。

分析結果を見た運営者が都度指名する方式を避ける。

可能なら、事前登録された複数候補からの交代制・抽選等を利用する。

---

## 13.3 Local Actor の選出

既存ハブの推薦だけで選ばない。

```text
open nomination
+
stratified selection
+
random slots
```

等、複数経路を組み合わせる。

「地域代表」という単一人物を置くこと自体を避け、複数Bを残す。

---

## 13.4 自動警報型と解釈判定型

### 自動警報型

あらかじめ測定可能な条件。

例：

- 観測努力量の急変
- 個人識別情報の流出
- 特定指標だけの極端な最適化
- Core Panel の無記録変更
- Core Staleness Review の期限超過
- 同一参加者への高反応性質問の過剰反復
- 撤回要求の未処理滞留
- Configuration Declaration と実運用の不一致
- Governance Load の継続的超過、または未処理レビューの増加

条件成立時に自動でレビューへ送る。

### 解釈判定型

例：

- 地域循環が善として固定化された
- 住民の選択可能性が低下した
- 特定文化への偏見が分析へ侵入した

複数主体によるレビューを必要とする。

判定結果には、

```text
Trigger
Evidence
Dissent
Decision
Next Review
```

を残す。

意見が一致しない場合、その不一致自体をξとして保持する。

---

## 13.5 Expected Response Window 超過

期限を超えた介入は、自動成功・自動失敗のどちらにも分類しない。

```text
Out-of-Window
↓
§13.1 の複数主体Review
↓
{延長, 仮説変更, 介入停止, 観測継続のみ}
```

介入運営者だけで延長を決定してはならない。延長時は理由・反対意見・次回判定時点を記録する。

---

個人識別情報、一意に人物へ帰着する役割記述、不必要な詳細 W_ij、撤回済みデータ、政策判断に不要な機微情報を除外・集約する。

```text
Person
→ Role Vulnerability
→ Structural Break
→ Intervention Option
```

を中心表現とする。

## 14.3 Public Package

Policy Decision Package からさらに、少数セル・希少役割・細粒度地理・個別関係経路・再識別につながる組合せを抑制する。

## 14.4 Claim Envelope

Research / Policy / Public のいずれの成果物でも、出力単位ごとに最低限、

```text
config_level
claim_limits
OPD_ID
release_layer
```

を付与する。

主張限界を除去した複製物は、本プロトコル準拠成果物として再利用してはならない。

## 14.5 Release Gate

```text
Consent / Withdrawal Check
→ Privacy Review
→ Re-identification Test
→ Output-layer Transformation
→ Release Decision
```

Privacy Review を公開後の説明にしてはならない。

## ■ 16. 最短原則

本プロトコルを一文へ圧縮すると、

> **地域に何があるかではなく、何が何を支え、何が流れ、どこで切れ、どう再生産されているかを調べる。さらに、その観測自体が何を見落としているかも調べる。**

圧縮形：

```text
Baseline Discovery
→ Core Freeze + Exploratory
→ {B, SILN_i, W_ij, Flow_k}
→ Break / Regeneration / Vital Signs
→ Human Review
→ ΔW intervention
→ Re-observe

並行：
Observation → Reactivity → ΔW / ΔFlow
Exploratory → Core Promotion Review
RDL Translation → ξ_translation
AI → ξ_candidate

常時：
ξ ≠ 0
Observation ≠ Neutral
```

さらに運用上は、

```text
測定系を改良しても、
基準尺まで毎回作り直すな。

見えないものを探せ。
ただし、探し方が変わったことも記録せよ。

人ではなく役割の脆弱性を見る。
しかし、役割の背後にいる人を消すな。

成功だけでなく失敗を探せ。

RDLに入ったものだけを見るな。
RDLに入らなかったものも記録せよ。

AIが未知を語ったことを、
未知を観測したことと取り違えるな。

フル構成を維持できないなら縮退せよ。
ただし、縮退した分だけ主張も縮退させよ。
```

政策は観測の後に置く。

## ■ 17. 現段階の位置づけ

本プロトコルは、完成した社会科学的方法論ではない。

生態学的調査法から、

**存在・利用・移動・接続・流れ・再生産・検出不確実性・反復観測**

という操作原理を抽出し、RDLの地域観測へ再仮設したものである。

v0.3は **PRE-FIELD CANDIDATE** と位置づける。

v0.1〜v0.3 の主要な更新入力は、実地反例ではなく内部整合性・破断候補に対する机上検査であった。したがって、内部整合性の向上を実地適用可能性の実証と取り違えてはならない。

本版では Minimum Viable Configuration を含む運用縮退規定までを実地前の最終設計範囲とし、以後の新機能追加を原則凍結する。

```text
v0.3
= Pre-field Candidate / Specification Freeze

次の実施段階
= Pilot 0（Config S 実行可能性破壊試験）

次の主要改版入力
= Baseline Discovery の実施結果
```

実地前に許容する更新は、原則として、

- 誤字・参照切れ
- 明白な内部矛盾
- 安全・権利上の重大欠陥
- 実施不能性が事前に確定した項目

に限定する。

**v0.4 の主要改版入力は Baseline Discovery / 初回運用で得られた実地破断とする。**

v0.3では、v0.2の自己観測層に加えて、

```text
地域生態
↕ 観測・反応性
観測系
↓ 再観測

Exploratory
↔ Core昇格検査

RDL
↓ 再翻訳検査

AI
↓ 限界検査

成果物
↓ 出力層別化
```

という双方向自己観測・統治層を追加した。

したがって、今後の実地適用によって、

- 観測不能な変数
- 不要な分類
- 足りないFlow
- プライバシー上の破断
- 地域ごとの異質性
- 指標間の非可換性
- Core Panel の維持困難性
- RDL翻訳不能性
- AI支援が逆に増やすバイアス
- 観測行為が地域へ与える反応性
- Core Panel が固定化する可視性バイアス
- 同意・撤回・出力層の運用破断
- Governance Load が実運用能力を超える地点
- 時間以外の C_social / C_psych / C_institutional が実施を阻害する地点
- Config S / M / L の境界が実態に合わない事例
- 「削れない」項目が現場で最初に脱落する事例
- Protocol_designed と Protocol_executed の乖離
- Claim Envelope が二次利用時に失われる経路
- 縮退時の claim limits が過剰または不足している事例

を発見し、更新されることを前提とする。

**地域だけを測るな。地域を測っている自分たちの観測系と、その観測が地域へ返す作用も測れ。**
